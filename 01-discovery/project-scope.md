# Project Scope: Kudu Bucks Self-Service Top-Up Solution

## 1. Project Purpose

The purpose of this project is to analyse the challenges associated with topping up Kudu Bucks accounts when physical cash-loading machines are unavailable and design a proposed digital self-service solution.

The project will demonstrate the application of Business Analysis techniques, from defining the problem and requirements to designing a prototype and developing test scenarios.

## 2. Problem Being Addressed

Based on personal experience, Kudu Bucks cash-loading machines can sometimes be unavailable, making it difficult to add funds when needed for printing.

This project will explore whether a digital top-up option could provide a convenient alternative.

## 3. Project Objectives

- Understand the existing top-up process using available information.
- Identify the needs of students who use Kudu Bucks for printing.
- Define and prioritise business and system requirements.
- Design a proposed digital top-up process.
- Create a clickable mobile prototype.
- Develop test scenarios to assess the proposed solution.

## 4. In Scope

The project will include:

- Documenting the initial problem and available research.
- Mapping the existing top-up process based on available evidence.
- Defining user needs, requirements and business rules.
- Comparing potential solution options.
- Designing the proposed future-state process.
- Creating mobile wireframes and a clickable prototype.
- Developing user stories, acceptance criteria and test cases.
- Defining measures for evaluating the proposed solution.

## 5. Out of Scope

The project will not include:

- Building a production-ready financial application.
- Processing real payments or transferring real funds.
- Connecting to the actual Kudu Bucks system.
- Accessing confidential university systems or student account information.
- Making changes to existing Wits systems.
- Claiming that the proposed solution has been approved by Wits.

## 6. Assumptions and Constraints

- The project is based on personal observations and publicly available information.
- The proposed solution is a concept and has not been approved by Wits.
- The current system's technical architecture and integration capabilities are not known.
- The prototype will use fictional account details and simulated transactions.
- Any real implementation would require technical feasibility assessment, appropriate permissions and relevant security controls.

## 7. Expected Deliverables

The expected deliverables are a project case study, process diagrams, requirements documentation, a solution design, a clickable prototype and a testing plan.

## 8. Success Criteria

The project will be considered complete when:

- The problem and project scope are clearly documented.
- Requirements are defined and prioritised.
- The proposed process is documented.
- The prototype demonstrates the main top-up journey.
- Test cases cover successful and unsuccessful transactions.
- Assumptions, limitations and outstanding feasibility questions are documented.
